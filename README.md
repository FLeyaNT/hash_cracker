# HashCracker

Учебный переборщик паролей для MD5, SHA-1, bcrypt и Argon2id на C# / WPF (.NET 10, Windows).

## Запуск

Откройте `HashCracker.slnx` в Visual Studio или выполните:

```powershell
dotnet build HashCracker.slnx --configuration Release
dotnet run --project HashCracker --configuration Release --no-build
```

Перед пересборкой закройте работающий экземпляр из той же папки вывода: Windows блокирует его EXE.

## Параметры поиска

- Выберите алгоритм и вставьте хэш. Для MD5 требуется 32, для SHA-1 — 40 шестнадцатеричных символов.
- Выберите готовый алфавит или пункт «Свой алфавит». Повторы автоматически удаляются с сохранением порядка первого появления. Пробел допустим в собственном алфавите.
- Все алгоритмы используют UTF-8. Длина считается в кодовых точках Unicode: например, отдельный символ `😀` занимает одну позицию. Составные символы и последовательности emoji могут занимать несколько позиций. Нормализация Unicode не выполняется: разные последовательности байтов дают разные хэши.
- Длины — от 1 до 128. Минимальная длина не должна превышать максимальную.
- Число комбинаций рассчитывается точно с проверкой переполнения. Диапазон с более чем `9223372036854775807` комбинациями отклоняется до запуска. Это предел счётчика, а не обещание завершить такой перебор за приемлемое время.
- Число поисковых задач выбирается от 1 до количества доступных логических процессоров. Для каждой длины создаётся общая очередь первых символов в порядке алфавита. Задача забирает один свободный символ, перебирает все комбинации остальных позиций с этим первым символом, затем забирает следующий ещё не выданный символ. Символ выдаётся только одной задаче. Задач создаётся не больше, чем уникальных символов алфавита. Это правило одинаково для всех алгоритмов, включая Argon2.

Например, при алфавите `0123456789`, длине 6 и восьми задачах первые назначения — цифры `0`–`7`. Задача с цифрой `3` проверяет `300000`–`399999`. Первая освободившаяся задача забирает `8`, следующая — `9`. Если свободных первых символов больше нет, завершившая свою работу задача останавливается. После завершения всех задач программа переходит к следующей длине и создаёт очередь заново. Порядок выдачи символов определён; порядок завершения задач зависит от их выполнения.

## bcrypt и Argon2

Поддерживаются bcrypt `$2a$`, `$2b$`, `$2y$`; для этой программы cost ограничен диапазоном 04–16. Диапазоны паролей, в которых возможны строки длиннее 72 байт UTF-8, отклоняются, чтобы не выдавать результат для усечённого пароля.

Поддерживается только Argon2id версии 19. Параметры `m`, `t`, `p` можно записывать в любом порядке; неизвестные и повторяющиеся параметры отклоняются. Принимается корректный Base64 с заполнением `=` или без него.

Ограничения ресурсов этой программы (не универсальные ограничения алгоритма):

- `p`: 1–16;
- `m`: от `8*p` до 262144 КиБ;
- `t`: 1–100;
- соль: 8–1024 байта; результат: 4–1024 байта;

Общего лимита памяти, уменьшающего число задач Argon2, нет. При `m=65536` восемь одновременно работающих проверок используют около 512 МиБ памяти Argon2, десять — около 640 МиБ, плюс накладные расходы. Ограничение `m` выше относится к одной проверке. Выбранное число задач сохраняется с учётом размера алфавита.

Хэши из задания с bcrypt cost 10 и Argon2id `m=65536,t=3,p=2` укладываются в эти ограничения.

## Остановка и результаты

Отмена проверяется перед каждой попыткой. Уже начавшееся вычисление bcrypt или Argon2 завершается внутри библиотеки: принудительного прерывания криптографической функции нет. Остальные кандидаты после сигнала не запускаются. Завершение поиска ожидает все созданные задачи.

Результаты различаются:

- `Found` — найден подходящий пароль;
- `Exhausted` — проверен весь заданный диапазон;
- `Cancelled` — поиск отменён, часть вариантов не проверена.

Счётчик включает завершённые проверки всех задач, в том числе тех, которые уже выполнялись в момент нахождения пароля. Время измеряется для самого поиска, до записи CSV. При закрытии окна активный поиск отменяется, после завершения задач результат сохраняется, затем окно закрывается.

Журнал окна сохраняет все запуски текущего сеанса. Каждый завершённый или отменённый запуск автоматически добавляется в `%LOCALAPPDATA%\HashCracker\results.csv`. Кнопка «Сохранить CSV» экспортирует результаты текущего сеанса в выбранный файл. Если автоматическая запись недоступна, результаты остаются в памяти и доступны для ручного экспорта до закрытия окна.

CSV использует UTF-8 с BOM, разделитель `;`, экранирование кавычек и переносов строк. В нём сохраняются время запуска с часовым поясом, алгоритм, исходный хэш, фактический алфавит, длины, выбранное число потоков, максимальное число созданных поисковых задач на одну длину, статус, точное время поиска, попытки, общее число комбинаций и найденный пароль.

Индикатор прогресса оставлен в прежнем виде: анимация выполнения без процентов.

## Как читать код перебора

Основной алгоритм находится в `HashCracker/Services/BruteForcer.cs`. Начните с `RunAsync`: он проверяет параметры, запускает поиск для каждой длины и формирует результат. `SearchLengthAsync` создаёт задачи, а `SearchWorker` забирает первые символы из общей очереди и проверяет кандидатов.

Вспомогательные методы: `WritePasswordBytes` собирает UTF-8-представление пароля, `MoveToNextSuffix` переключает остальные позиции как счётчик, `MatchesHash` проверяет совпадение с хэшем. `Cancel` подаёт сигнал остановки, а `ShouldStop` объединяет отмену пользователем и остановку после нахождения пароля.

Проверки входных данных и разбор хэшей находятся в `BruteForcer.Validation.cs`. Оба файла объявлены с `partial`: это две части одного класса, поэтому они используют общие методы и поля.

## Проверки

Проект `HashCracker.Tests` — запускаемый набор проверок без дополнительных тестовых пакетов:

```powershell
dotnet build HashCracker.slnx --configuration Release
dotnet HashCracker.Tests/bin/Release/net10.0-windows/HashCracker.Tests.dll
```

Проверяются полнота перебора на небольших наборах, точность количества попыток, все четыре алгоритма, UTF-8, удаление повторов, отмена, повторный запуск, запрет одновременных запусков одного экземпляра, проверка форматов и ограничений, а также сохранение и чтение CSV со спецсимволами. Эти проверки не заменяют сравнительные эксперименты с hashcat или John the Ripper.
